# Mac Settings and the Windows/Linux settings page

Every control of the Mac app's Settings window (Sources/MiniGateway/Settings.swift) and its counterpart in
`minigw serve` (the settings page `/minigw/settings`, the admin API in [admin-api.md](admin-api.md) and
`serve.json`). Mac only: Siri AI, Apple Foundation Models, the WebDAV folder mount (direct mode), native mode,
`minigw run`, and the build network switches of worktree mode.

| Mac pane · control | Windows/Linux | API field | Note |
|---|---|---|---|
| Sidebar: search, items with icons, + (LiteLLM, OpenRouter, other) / − | same | – | Same order: General, providers, (Siri AI, Apple FM: Mac only), Foundry Local, Claude CLI, Codex CLI, Copilot CLI, Grok CLI, Devices. |
| Built-in providers LiteLLM and OpenRouter | same | `GET providers` | Always listed, off until a key is set, can be turned off but not removed or renamed (`DELETE` 400). Defaults: LiteLLM `http://localhost:4000` with Allow http, OpenRouter `https://openrouter.ai/api` with no model enabled. A provider named litellm or openrouter is the built-in one. |
| General · Open at Login | General · Start at sign-in | `PATCH general {startAtSignIn}` | Windows: Run value for the tray. Linux: `minigw serve install`. |
| General · Address, Port | same | `general.address`, `general.port` | Address only empty, `0.0.0.0`, `::` or `127.0.0.1` (the admin API needs 127.0.0.1); a change needs a restart. |
| Devices · Allowed clients (IP; empty = all) | same | `general.allowedClients` | Connections from other IPs are closed; this computer is always allowed. |
| Devices · Allow unencrypted connections from other Macs | Devices · Allow unencrypted connections from other computers | `general.allowPlainRemote` | Such clients have no device key: they also need "Allow any device" (Devices). |
| General · Token: Show, Copy Token, New Token | same | `GET general.connect`, `POST general/token` | A new token also ends settings page sessions. |
| General · Allow this user's apps without a token | same | `general.allowLocalApps` | On by default. Model requests from this user's own programs on this computer (not the gateway's agents, not web pages: an Anthropic header, loopback Host, no Origin). Mac: libproc; Linux: `/proc/net/tcp` uid; Windows: process SID. Mac exception: sandboxed apps of this user, including commands from Claude Code's sandboxed Bash, need the token (they cannot be told apart from the gateway's agents). Apps in a web view send Origin and need the token everywhere. |
| General · Scratch folder: Choose…, Default, Show in Finder | Scratch folder: path field, Choose… (Windows tray), Default | `general.scratch` | With the Windows tray Choose… opens the folder dialog; on Linux and without the tray the path is typed. No Show in Explorer. A new folder applies to new sessions, existing copies are not moved. |
| General · About: Version (build), License | same | `status.version`, `status.build` | |
| Provider · Enabled (off without a key) | same | `PATCH providers/{name} {enabled}` | |
| Provider · Name, Base URL, Allow http (localhost, a private IP or a .local name only) | same | `PATCH providers/{name} {name, baseURL, insecure}` (Mac: Settings, `POST providers`) | Same rule on both: `https`, or `http` with Allow http to localhost, a private IP or a `.local` name (not a name without a dot: a DNS search domain can make it public). Mac providers with such an `http` URL from before keep working (Allow http on); others need `https`. Renaming moves the key (Go). |
| Provider · API key (saved; enter to replace) | same | `POST providers {name, baseURL, key, insecure}` | Key in Credential Manager / Secret Service, never shown. |
| Provider · Models: search, N of M enabled, Enable All, Disable All, refresh, a switch per model, context size | same | `GET/POST providers/{name}/models` | Enable All = all, also future models. |
| Provider · Aliases (advanced) | same | `PATCH providers/{name} {aliases}` | `alias = upstream ID, window` per line; when set they define the models. |
| Sidebar + / − for providers | same | `POST providers`, `DELETE providers/{name}` | |
| Devices: allow any device, allowed clients (IP), waiting (editable name, ID, address, time, OS and minigw version; Allow/Reject; warning when the name equals an allowed device's), allowed (rename, ID, last seen, OS and minigw version; Copy ID, Remove) | same | `devices`, `PATCH devices/{id} {name}`, `general.allowAnyDevice`, `general.allowedClients` | Same pane and approval on both; waiting devices also in the menu bar (Mac) and tray (Windows). Siri per device stays in the Mac's Siri pane; unencrypted connections: Mac "from other Macs", Go "from other computers". |
| Claude CLI · Enabled | same | `agents/claude.enabled` | |
| Claude CLI · Executable, Choose…, detected path and version | Executable, Find, Browse… (Windows tray), detected path and version | `agents/claude.path`, `.exe`, `.version` | With the Windows tray Browse… opens the file dialog (also for Codex, Grok and Copilot); on Linux and without the tray the path is typed. Find auto-detects. |
| Claude CLI · Allowed folders (+/−) | same | `agents/claude.folders` | Absolute paths, not near the config folder; also `--add-dir` and the sandbox. |
| Claude CLI · Allow local tools, tool table (exclude) | same | `.allowLocalTools`, `.disabledTools`, `GET agents/claude/tools` | On Windows it needs "Allow commands without a sandbox" (no sandbox for Bash). |
| Claude CLI · Tools (text), Permission mode | Tools (switches), Permission mode | `.tools`, `.permissionMode` | Only without local tools, as on the Mac. |
| Claude CLI · Setting sources | same | `.settingSources` | Default empty on both; the old Mac default `project,local` migrates to empty (hooks from an agent's folder would run outside the sandbox). |
| Claude CLI · Command-line tool: Install, Download… | Command-line tool: status, Download… | `status.installDir` | Installed with `minigw serve install`. |
| Codex CLI · Enabled, Executable | same | `agents/codex.enabled`, `.path`, `.found` | Off by default. Models `claude-codex` (default model) and `claude-codex-<slug>`. Windows: the native `codex.exe` (also the one inside the npm package). |
| Codex CLI · Models: a switch per model, Enable All, Disable All | same | `agents/codex.models`, `GET agents/codex/models` | From `codex debug models`; null = all, also future ones. |
| Codex CLI · Allowed folders | same (shared with Claude CLI) | `agents/claude.folders` | Passed as `--add-dir` in workspace-write. |
| Codex CLI · Sandbox: Allow writing, Allow network access | same | `.write`, `.network` | `workspace-write` with `sandbox_workspace_write.network_access`, else `read-only`; resume with `codex exec resume <thread>`. Network is off by default (Mac and minigw serve). On Linux Codex uses Landlock and seccomp, which do not limit reads, so the gateway also refuses admin requests from agent processes, and Codex and Grok run under `bwrap` with the home and config folders empty (tmpfs), only the program folders (read-only), `~/.codex` or `~/.grok`, the synced copy and the allowed folders mounted back, and without the D-Bus session (Secret Service, `/tmp/dbus-*`). Without a working `bwrap` they run only with "Allow commands without a sandbox", as on Windows. Under bwrap only the exact PATH folders under home and the CLI's package (an nvm version, or the folder with its package.json) come back read-only; `.ssh`, `.gnupg`, `.config`, `.cargo/credentials*`, `.local/share/keyrings` stay hidden even inside them; `XDG_RUNTIME_DIR`, `/tmp/dbus-*` and `/tmp/ssh-*` are empty, and `SSH_AUTH_SOCK`, `GPG_AGENT_INFO`, `GNOME_KEYRING_CONTROL`, `DBUS_SESSION_BUS_ADDRESS` are dropped (also without bwrap). Each device has its own `CODEX_HOME` / `GROK_HOME` in `<scratch>/state/<device>/`, with `auth.json` (and `config.toml`, Grok's `auth.json.lock`) linked to the real one, so devices do not see each other's sessions; Windows has no per-device state (links need extra rights there). On the Mac all devices share `~/.codex` and `~/.grok`. Sync and worktree mode (worktree refused without writing), also for requests without tools (then read-only). |
| Grok CLI · Enabled, Executable | same | `agents/grok.enabled`, `.path`, `.found` | Off by default. Models `claude-grok` (default model) and `claude-grok-<slug>`. Windows: only a native `grok.exe` (no npm/cmd wrapper). |
| Grok CLI · Models: a switch per model, Enable All, Disable All | same | `agents/grok.models`, `GET agents/grok/models` | From `grok models`; null = all, also future ones. |
| Grok CLI · Sandbox: Allow writing | same | `.write` | `--sandbox workspace --always-approve`, else `--sandbox read-only`; resume with `-r <session>`. Grok has no network switch (`PATCH {network}` is 400); read-only also has `--disable-web-search`. The config folder is also denied with `--deny Read/Edit/Write(<config>/**)`; that is defence in depth only (Grok matches paths in its tools and commands, an obfuscated path can get past it): the protection is bwrap on Linux, the opt-in on Windows and the admin API check. Sync mode only: Grok refuses worktree, as on the Mac. |
| Copilot CLI · Enabled, Executable, Models | same (models as a comma-separated field) | `agents/copilot.enabled`, `.path`, `.found`, `.models` | Off by default. `claude-copilot` (Copilot's default, `auto`) and `claude-copilot-<model>` for each listed name; Copilot has no model list. |
| Copilot CLI · Allow writing, Allow web access, Allow commands | same (commands confirmed in a dialog) | `.write`, `.network`, `.commands` | `copilot --output-format json` (prompt on stdin, not in argv), never `--allow-all-*`/`--yolo`: `--allow-tool read`, plus `write`, `url`, `shell` when switched on; `memory` and, with commands, `shell(gh:*)`, `shell(security:*)` denied. Always `--disallow-temp-dir`, `--disable-builtin-mcps`, `--no-ask-user`, `--no-auto-update`, `--disable-client-telemetry`, no `--add-dir`; every inherited `COPILOT_*`, `GH_TOKEN` and `GITHUB_TOKEN` dropped. Sessions by `--session-id`. Each request gets a fresh `COPILOT_HOME`, deleted afterwards; only `session-state/<id>/events.jsonl` and `workspace.yaml` are kept between turns, where the sandbox cannot reach it. Mac: always in a `sandbox-exec` profile (writes only to the folder with writing on, and its temporary folder; `~/Library/Caches` read-only). minigw serve: under bwrap on Linux (`~/.cache/copilot` read-only, own PID namespace), Windows only with "Allow commands without a sandbox" and with the real `~/.copilot`. Sign-in: the write-only `token` (fine-grained PAT, Copilot Requests only), passed as `COPILOT_GITHUB_TOKEN`; the Mac requires it for every request, commands require it everywhere; Linux without commands may use the gateway's environment token or `gh auth token`. Only `events.jsonl` and `workspace.yaml` of a session are kept. A new Copilot binary or a missing package cache: one `copilot --version` unpacks the package, without network and with writing only to the package cache and temporary folders (`sandbox-exec` on the Mac, bwrap on Linux; Windows has no sandbox); allowed folders and the agents' working folder may not contain or be inside the package cache. Sync and worktree on minigw serve (worktree refused without writing); on the Mac also native. |
| – | Codex CLI, Grok CLI, Copilot CLI on Windows, and on Linux without `bwrap` | `agents/claude.allowUnsandboxedBash`, `status.agentsUnsandboxed` | Without "Allow commands without a sandbox" they do not run at all: there they can read and change everything the user can, including the gateway's settings. Devices that use Codex or Grok can read every file this user can read. |
| – | Claude CLI · Allow commands without a sandbox; folder for agents without sync | `.allowUnsandboxedBash`, `.folder` | Windows has no sandbox for commands; minigw serve only. |
| Apple Foundation Models (Mac only) | Foundry Local · Enabled, Executable, Models (a switch each, Enable All, Disable All), Instructions | `GET/PATCH foundry`, `GET foundry/models` | Microsoft Foundry Local on Windows, Linux and the Mac (both panes; on the Mac next to Apple FM). Models `claude-foundry-<model>`, conversation only; the gateway starts `foundry server` and loads the model. The port is used only when its listener is this user's process inside Foundry's install folder, checked on every request; not yet verified with the winget (MSIX) install on Windows (windows-test-checklist.md → Foundry Local). |
| General · Worktree mode: Network for builds, Network for Codex builds | – | `worktreeNetwork` (Mac config) | Worktree mode itself works on both (`--minigw-work=worktree`, mirrors in `scratch/repos`, clones in `scratch/worktrees`). minigw serve has no network switches: on Linux the agents' sandboxes decide (Claude Code's network rule, bwrap shares the network), on Windows there is no sandbox. One clone per session and agent; agent requests run one at a time per device and repository, also across that device's sessions (the Mac runs parallel requests in separate clones). Grok and agents without writing refuse worktree on both. |
| General, minigw run: devices, network | – (Mac only) | `GET/PATCH run` | Needs native mode (the folder is the Mac's SMB share) and a sandbox-exec profile; not planned for minigw serve. |
| Native mode (`--minigw-work=native`) | – (Mac only) | `POST /minigw/native` | The client's folder is an SMB mount of a gateway share; minigw serve refuses it (auto then picks worktree or sync). |
